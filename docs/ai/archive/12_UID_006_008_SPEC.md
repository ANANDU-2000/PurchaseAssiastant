# Desktop UI Fixes — Specs (UID-006 to UID-008)

Appends to `09_UID_desktop_fixes_SPEC.md`. Check a box only when the diff proves it.

---

### UID-006: System-stock saves show visible success acknowledgment
- [x] Saving a stock update in **System** mode shall show a clear success `SnackBar` with
  `SnackBarBehavior.floating` (and keep Undo when applicable).

### UID-007: Stock row/detail must update after System save
- [x] Confirm whether patch builders can return empty for a valid System-mode save; report
  field-mismatch vs safety-net in the implementer summary.
- [x] If patch is empty, fall back to the locally entered quantity so list/detail never silently
  skip updates. Harden `system_qty` as an alias for `current_stock` in the detail patch builder.

### UID-008: Short fields use `AppFormRow` on stock modal + wizard steps
- [x] `quick_stock_action_sheet.dart` pairs short fields with `AppFormRow` (notes stay full-width;
  mode toggle not wrapped).
- [x] `purchase_fast_items_step.dart`, `purchase_party_step.dart`, and
  `purchase_review_tally_step.dart` wrap naturally short pairs in `AppFormRow`.

## Why these exist

- **UID-006** — save works but user cannot tell (trust).
- **UID-007** — stale numbers after a successful save (data trust).
- **UID-008** — half-adopted design system causes full-width stacked fields on desktop.
